## Implemented correction

1. Existing forecast_consistency workflow runs one combined binding/horizon check instead of projecting the same pair twice. The combined command already performs both checks. Existing regressions remain.
2. verify_dawn_revisions.py resolves each supplied ref once to a commit and reads both files from that commit. It verifies the committed binder matches the locally executing reviewed binder. A process-local successful-pair memo uses exact bytes (stronger than trusting user-supplied hashes); output records SHA-256 and commit provenance. Failed validations are never cached; no persisted cache can manufacture PASS.
3. Every lookup still checks offset-aware review time, nonfuture/current America/Chicago issue date, production season and exact three-day horizon. Results explicitly say BINDING_ONLY_NOT_SOURCE_FRESHNESS_OR_SCIENTIFIC_ACCEPTANCE. Historical --as-of replay cannot be called current acceptance.

Usage in the existing Dawn review session:
```
python -B model_data/verify_dawn_revisions.py --root . BASE_COMMIT RECEIPT_MERGE_COMMIT
```
Use the existing local repository; do not fetch history or create another clone just to generate a cache hit. Verify after publication using freshly resolved main; if main advanced, process its exact pair. Do not omit the source-freshness/observation review.

## Further reuse contract (specified, not implemented)

| Work | Reuse key | Mandatory invalidation / work retained |
|---|---|---|
| Git comparison | repository + exact base/head commits + comparison mode + tool version | Either commit/mode/tool change; resolve refs freshly; never cache network failure as no change |
| Static configuration validation | complete dependency file hashes + validator/dependency versions + options | Any dependency change/missing file; mutable host task/service state remains a fresh read |
| Observation integrity | record + capture/status/burst/vision/frame hashes + validator/schema versions | New or corrected record/frame, changed validation contract; evaluate target-window eligibility separately |
| Public-log parsing | exact log blob + parser version | New blob/parser; always evaluate the current observation window; no evidence stays UNKNOWN |
| Source parsing | exact raw/manifest hashes + parser/schema versions | New/corrected bytes; always recompute availability, age, geometry and admission at issue time |
| Human-facing report | material disposition + evidence identity under existing gate | New material event/fault/recovery/deadline; preserve evidence even when message suppressed |

Do not memoize a whole daily PASS, source freshness, current camera availability, mutable schedules, UNKNOWN admission, or alert disposition by probability equality. Do not use current-state main SHA alone as the static key: unrelated register appends cause false misses. Do not use a subset configuration hash without enumerating the validator's entire dependency closure.

The process-local binding cache deliberately does not provide cross-run science caching. A durable cache needs owner-reviewed dependency manifests, trusted producer receipts, failure/partial-result exclusion, atomic publication and provenance references; retain complete daily checks until that integration is tested.
